# 账户池与错误治理

## 账户调度

AccountPool 面向 Provider 调用提供账号选择和执行边界。它选择健康账号，使用租约避免同一账号并发冲突，并记录失败次数与冷却时间。账号健康状态是调度信号，不应被直接暴露为凭据或内部异常详情。

单账号串行化的原因是 Gemini Web 会话包含 session 上下文和上游状态；并发复用同一会话可能造成请求交叉、状态覆盖或错误归因。

## 错误分类

错误应尽量保持可区分，至少包括：

- 认证失效：需要刷新 Cookie 或重新登录；
- 限流：短期请求频率超过上游限制；
- 配额耗尽：账号额度不可用；
- 上游不可用：网络、代理或 Gemini Web 暂时失败；
- 协议变更：上游 RPC/响应结构无法解析；
- 不支持能力：例如图像生成；
- 请求无效：外部 schema 或参数不合法；
- 请求取消：客户端主动断开或超时终止。

分类用于决定 HTTP/SSE 映射、账号冷却和是否可以重试，不能用一个笼统的“服务器错误”覆盖全部场景。

## 重试安全边界

仅当尚未向下游发送内容，并且能够确认上游没有接受或执行请求时，重试才安全。收到 session 或 text 事件后，执行已经产生可观察副作用，不能自动切换账号，否则会导致重复回答、上下文错乱或客户端收到两段结果。

流式响应已发送 headers 后，错误必须编码为终态事件；不能返回新的 JSON 状态码。取消必须释放租约、停止读取上游流并清理定时器。
